# Plan — DEMO 3/4: Bouwplaats Chaos (grywalna gra) · 2026-11-17

**Cel / Goal:** kafelek „Game · Qualify cold attention" → `/lab/game/` = **grywalne demo**. Klient gra, zdobywa wynik, przechodzi bramkę rejestracji, dostaje kupon — i **kupon realnie nalicza rabat w Wizard demo** (żywy handoff między drzwiami).

**Sesja:** 1 · **Priorytet:** P2 · **Zależności:** Demo 1/4 (Wizard) LIVE — kupon musi mieć gdzie zadziałać

## Zakres
**IN:**
- `GameDemo.tsx` (`'use client'`) — gra „whack-a-hazard" na siatce: **klikasz zagrożenia (+punkty), unikasz dobrych obiektów (−punkty)**
- **5 aktów** rosnącej trudności (szybkość + gęstość), timer per akt, wynik sumaryczny
- **Bramka rejestracji** (imię + email — demo, nic nie wychodzi) → progi wyniku = poziom kuponu (np. GAME10 / GAME15 / GAME20)
- **Handoff:** CTA „Use your reward in the Wizard" → `/lab/wizard/` + zapis kuponu do `sessionStorage['qf-demo-coupon']` (Wizard demo nalicza rabat — patrz Plan 1/4)
- Ekran „Game over": wynik, ranking sezonowy (statyczny demo-leaderboard z wynikiem gracza wstawionym), kupon
- Sterowanie: **klik/tap** (mobile + desktop); brak animacji dekoracyjnych — ruch tylko wynikający z interakcji, `prefers-reduced-motion` respektowane (gra bez migających/parallax elementów)

**OUT:** silnik gier/canvas · prawdziwy leaderboard backend · e-maile z kuponem · integracja z prawdziwym Wizard (tylko demo Wizard)

## Logika frontu (bez backendu)
1. Pętla aktu: losowe pojawianie się obiektów na siatce (klikalne pola), timer `setInterval`, punktacja +10/−5
2. Koniec aktu → krótki ekran wyniku → następny akt (5×) → game over
3. Rejestracja: walidacja email → nadanie kuponu wg progu → zapis do `sessionStorage`
4. Wszystko w stanie komponentu; czyszczenie timerów w `useEffect` cleanup
